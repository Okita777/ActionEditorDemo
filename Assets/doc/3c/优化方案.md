# Animancer 状态切换与 Root Motion 优化方案

## 1. 文档目的

本文针对当前 Locomotion 动画切换中的机械位移异常，提出一套从短期修复到生产级演进的代码优化方案。

当前重点问题：

- `Run_Start → Run` 时角色胶囊轻微后退；
- 增大 `Run` 的 `Transition Duration` 后，后退明显加重；
- 将 `Transition Duration` 设为 `0` 后大幅改善，但仍有轻微跳动，且姿势衔接不够丝滑；
- `Run_End → Idle` 时胶囊存在轻微滑动；
- 修改动画导入的 Root Transform 选项、关闭反向 Root Motion、将 CrossFade 设为 `0`，均不能完整解决问题。

本方案的目标不是继续依赖 `Transition Duration = 0` 规避问题，而是建立以下正式能力：

1. 状态切换和动画切换原子化；
2. 同层动画交接不再经过“停止旧动画、再播放新动画”的中间语义；
3. Root Motion 捕获、所有权和消费策略彼此分离；
4. 状态边界的 Root Motion 样本不能跨状态误消费；
5. 视觉 Pose CrossFade 与机械 Root Motion 交接可采用不同策略；
6. 保留动画作者制作的真实运动，同时防止切换帧异常位移；
7. 所有关键行为均可观察、可配置、可回归测试。

---

## 2. 已确认事实

### 2.1 Locomotion Layer 权重没有发生变化

运行时观察 Animancer Graph 已确认：

- Locomotion Layer Weight 始终为 `1`；
- 变化的是 `Run_Start` 和 `Run` 两个 Animancer State 的 Weight；
- 因此“Locomotion Layer 实际淡出到 0 后再淡入”不是本次明显后退的直接原因。

当前同一帧内虽然调用了旧 Layer 的 `StartFade(0)`，但随后目标动画又调用 `StartFade(1)`，前一次目标被覆盖，Animator 没有采样到 Layer Weight 为 0 的中间状态。

尽管如此，当前停止再播放的接口语义仍然不可靠，应当优化。

### 2.2 胶囊体发生真实位移

异常不是单纯的视觉模型偏移。机械胶囊发生位移意味着异常数据最终进入了以下链路：

```text
Animancer 混合动画
	→ Animator.deltaPosition
	→ RootMotionSource.OnAnimatorMove
	→ CharacterVelocity.RootMotionVelocity
	→ CustomCharacterController
	→ KCC
```

### 2.3 CrossFade 时间会放大问题

已观察到：

| `Transition Duration` | 表现 |
|---:|---|
| `0.2s` | 明显后退，衔接更不自然 |
| `0s` | 后退大幅减轻，但仍有轻微跳动 |

这说明明显后退主要与两个 State 在过渡期共同参与 Animator Root Motion 求值有关。

`Transition Duration = 0` 只是绕过了持续混合，不能作为最终解决方案。

### 2.4 当前 Root Motion 缓存不识别状态边界

`RootMotionSource` 当前只累积：

```text
PositionDelta
RotationDelta
SampleCount
```

它不知道样本属于：

- 哪个状态；
- 哪次动画切换；
- 哪个 Animancer Layer；
- 切换前还是切换后。

由于状态机、Animator 和 KCC 分属不同更新阶段，旧状态样本可能在新状态 Movement Policy 生效后才被消费。

## 3. 根因模型

当前问题应按照两个层次处理。

### 3.1 过渡期间的混合 Root Motion

视觉 Pose CrossFade 的权重变化是合理的：

```text
Run_Start Weight：1 → 0
Run Weight：      0 → 1
```

但 `Animator.deltaPosition` 来自整个 PlayableGraph 的最终混合结果。若用简化模型表示最终根位置：

$$
p(t)=(1-w(t))p_s(t)+w(t)p_t(t)
$$

对时间求导后，除了源动画速度和目标动画速度的混合，还包含：

$$
\dot{w}(t)(p_t(t)-p_s(t))
$$

其中：

- $p_s$：源动画根位置；
- $p_t$：目标动画根位置；
- $w$：目标动画权重。

如果两个独立 FBX 的根轨迹绝对基准不同，那么权重变化本身也会制造额外位移。过渡时间越长，该异常越容易被肉眼观察为持续后退或滑动。

即使两段动画的脚步、姿势和速度相位相同，也不能证明它们的 Root Bone 绝对轨迹基准相同。

### 3.2 切换边界的一次性异常样本

当 CrossFade 为 `0` 时仍有轻微后退，说明还可能存在：

1. 旧动画 Pending Delta 被目标状态策略消费；
2. 新 Clip 首次求值建立根基准时产生异常 Delta；
3. 缓存 Animancer State 在重播前保留了旧时间或 Fade 状态；
4. 先 `Play()` 后设置目标 `Time`，使切换准备阶段读到旧播放时间；
5. `Animator.applyRootMotion` 在状态边界开关，导致内部基准重建；
6. Animator 的采样阶段与 KCC `FixedUpdate` 消费阶段不一致。

这部分不能通过继续调整动画 CrossFade 参数解决，需要在代码层建立状态边界保护。

## 4. 总体设计原则

### 4.1 单一机械根所有权

KCC 是角色机械根世界位置和旋转的唯一执行者。

Animator/Animancer 只负责：

- 动画 Pose 求值；
- 产生 Root Motion 样本；
- 不直接写正式角色根 Transform。

### 4.2 捕获不等于消费

必须分离两个概念：

- **Root Motion Capture**：Animator 是否稳定地产生 `deltaPosition/deltaRotation`；
- **Root Motion Consumption**：当前 Movement Policy 是否允许 KCC 使用这些 Delta。

不应通过频繁切换 `Animator.applyRootMotion` 表达状态运动策略。

### 4.3 状态切换是一次事务

一次状态切换必须具备完整上下文：

```text
Source State
Target State
Source Layer
Target Layer
Target Start Time
Fade Duration / Fade Mode
Root Motion Transition Policy
Transition Serial
```

不能再由独立的 `StopStateAnimation()` 和 `PlayStateAnimation()` 分别猜测切换语义。

### 4.4 视觉和机械运动允许使用不同交接规则

视觉 Pose 可以使用 `0.1～0.2s` CrossFade。

机械 Root Motion 应按明确策略交接，不能无条件使用最终混合图产生的根位置变化。

## 5. P0：原子动画状态切换

### 5.1 扩展动画控制接口

在 `ICharacterAnimationController` 中增加原子切换职责。建议引入：

```text
AnimationTransitionContext
├─ SourceState
├─ TargetState
├─ InterruptConfig
├─ TargetStartTime
├─ IsInterrupted
├─ IsSameOutputLayer
└─ TransitionSerial
```

接口职责调整为：

```text
PrepareStateAnimation
TransitionStateAnimation
StopAnimationLayer
SeekStateAnimation
StopAllStateAnimations
SetPlaybackScale
```

旧的 `PlayStateAnimation()` 可暂时保留为兼容入口，但内部应转发到统一切换实现。

### 5.2 同层切换规则

以下 Locomotion 切换属于同层交接：

```text
Idle → Run_Start
Run_Start → Run
Run → Run_End
Run_End → Idle
Turn_Back → Run
```

同层切换必须：

1. 保留旧 Animancer State 作为 CrossFade 来源；
2. 预先取得或创建目标 State；
3. 在 `Layer.Play()` 前设置目标 `Time` 和 `Speed`；
4. 只执行一次 `Layer.Play(target, fadeDuration, fadeMode)`；
5. Layer Weight 保持目标配置值；
6. 不调用旧 Layer 的 `StartFade(0)`；
7. 不在目标 State 成功安装前清空旧运行时信息；
8. 目标安装成功后才更新 `CurrentState`、`CurrentStateId` 等记录。

正确语义：

```text
Locomotion Layer Weight：保持 1

Run_Start State Weight：1 → 0
Run State Weight：      0 → 1
```

### 5.3 Layer 真正结束时才停止

以下情况才允许 `StopAnimationLayer()`：

- Action Layer 回到没有动画占用的空状态；
- UpperBody 覆盖完全结束；
- Additive 效果完全结束；
- 角色禁用、销毁或动画系统重建；
- 目标状态不再使用该输出层，且没有后继 State 接管。

`StopStateAnimation()` 不应继续作为每次状态切换的固定步骤。

### 5.4 调整目标 State 初始化顺序

当前顺序为：

```text
Layer.Play(target)
→ target.Time = startTime
→ target.Speed = speed
```

建议改为：

```text
GetOrCreateState(target)
→ 重置旧 Fade/播放残留
→ target.Time = startTime
→ target.Speed = speed
→ Layer.Play(target, fadeDuration, fadeMode)
```

复用缓存 State 时必须明确处理：

- 上一次播放时间；
- 上一次播放权重；
- 上一次 Fade 状态；
- `IsPlaying`；
- 动画事件状态；
- Directional Mixer 子 State 时间。

### 5.5 统一 Transition 参数所有权

一次动画切换只允许有一份 Transition 规格。

建议优先级：

1. 中断轨道的 Transition Override；
2. 目标状态的进入 Transition；
3. 系统默认 Transition。

源状态的 `Transition Duration` 不参与同层 CrossFade。源状态如需定义退出效果，应使用独立的 Exit Profile，并且只用于 Layer 真正退出等场景。

## 6. P1：稳定 Root Motion 生命周期

### 6.1 Animator 捕获保持稳定

对于使用自定义 KCC Root Motion 管线的角色，建议初始化后保持：

```text
Animator.applyRootMotion = true
```

角色是否真正移动，由当前 `StateMovementProfile` 决定：

- `TranslationMode`；
- `RotationMode`；
- 前向、侧向、垂直权重；
- Root Motion Rotation Weight；
- 是否允许反向位移。

例如 Idle 可以继续产生 Animator Root Motion 样本，但 Movement Policy 不接受平移时，`RootMotionSource` 应显式丢弃，KCC 不发生移动。

### 6.2 拆分 Root Motion 概念

当前 `AppliesRootMotion` 含义过多，建议拆分为：

```text
RootMotionCaptureEnabled       角色级：Animator 是否持续捕获
RootMotionOwnerLayer          Layer 级：当前谁拥有机械 Root Motion
RootMotionTranslationEnabled  状态级：是否提交平移
RootMotionRotationEnabled     状态级：是否提交旋转
```

所有权建议优先级：

```text
强制位移 Action
	> 普通 Action
	> Locomotion
	> 无 Owner
```

Owner 变化必须是原子的，不能在退出旧状态和进入新状态之间短暂变成 `None`。

### 6.3 Root Motion 所有权快照

每次 KCC 消费时，应读取一份已经提交完成的所有权快照，不读取状态切换过程中的临时值。

建议快照包含：

```text
OwnerLayer
OwnerStateId
TransitionSerial
TranslationMode
RotationMode
AxisWeights
AllowBackwardMotion
```

这样 Root Motion Delta 与消费它的 Movement Policy 可以明确对应。

## 7. P1：状态切换 Root Motion Barrier

### 7.1 为样本增加代次

扩展 `RootMotionDelta`：

```text
RootMotionDelta
├─ Position
├─ Rotation
├─ SampleCount
├─ Generation
├─ FirstSampleFrame
├─ LastSampleFrame
└─ OwnerStateId（仅诊断构建需要）
```

`RootMotionSource` 增加：

```text
CurrentGeneration
PendingGeneration
TransitionSerial
IsAwaitingFirstTargetSample
```

### 7.2 动画切换前建立 Barrier

原子切换开始时调用概念接口：

```text
BeginAnimationTransition(source, target, serial, policy)
```

职责：

1. 结束当前采样代次；
2. 明确处理旧 Pending，而不是让其自然残留；
3. 创建新代次；
4. 记录源状态和目标状态；
5. 标记下一次 `OnAnimatorMove()` 为目标切换首样本；
6. 防止旧代次 Delta 被目标 Movement Policy 消费。

### 7.3 旧 Pending 的处理规则

不能一律丢弃，也不能一律保留。建议：

| 场景 | 旧 Pending 处理 |
|---|---|
| 同层自然结束 | 在旧 Policy 下消费，或保存为源速度基准 |
| 同层中断 | 丢弃未消费位置，保留最后可信速度 |
| Root Motion Action 被强制打断 | 按动作中断策略决定消费或丢弃 |
| Root Motion → 非 Root Motion | 丢弃未消费位置，保留 KCC 当前真实速度供后续策略使用 |
| 非 Root Motion → Root Motion | 新代次首样本进入连续性校验 |
| 角色停帧、禁用、销毁 | 无条件丢弃 |

第一版可以采用更保守规则：状态切换时丢弃旧 Pending，同时保存最近一次已消费的可信速度。随后由首样本保护补偿连续性。

## 8. P2：切换首样本保护与速度连续性

### 8.1 不无条件丢弃第一帧

直接丢弃每次切换后的第一个 Delta 虽然简单，但会造成：

- 每次切换损失一帧运动；
- 低帧率下产生明显停顿；
- 高频连招累计距离误差；
- 位移攻击少走一段；
- 帧率相关结果。

因此“丢弃首帧”只能作为诊断模式或紧急兜底，不能作为默认生产策略。

### 8.2 保存最后可信速度

`RootMotionSource` 或独立的 Root Motion Resolver 应记录：

```text
LastStableLocalVelocity
LastStableWorldVelocity
LastStableYawVelocity
LastStableSampleFrame
```

切换后得到目标动画样本时，先计算：

$$
v_t=\frac{\Delta p_t}{\Delta t}
$$

然后进行连续性检查。

### 8.3 异常检测

建议检测以下条件。

#### 最大速度

$$
\lVert v_t\rVert>v_{max}
$$

#### 最大加速度

$$
\frac{\lVert v_t-v_{t-1}\rVert}{\Delta t}>a_{max}
$$

#### 方向突变

在输入方向和状态运动意图未反转时，如果：

$$
v_t\cdot v_{intent}<0
$$

则切换样本可能存在反向异常。

#### 位移尖峰

如果单样本位移显著高于该动画正常帧位移分布，应标记为 discontinuity。

阈值不能写死为全局常量，应来自角色或动画配置。

### 8.4 推荐策略枚举

建议增加：

```text
RootMotionTransitionPolicy
├─ RawAnimatorDelta
├─ DiscardFirstSample
├─ PreserveSourceVelocity
├─ BlendVelocity
└─ ClampDiscontinuity
```

推荐默认组合：

```text
Locomotion：BlendVelocity + ClampDiscontinuity
普通攻击：PreserveSourceVelocity 或 TargetDominant
冲刺/处决：Raw Authored Motion + Safety Clamp
调试模式：RawAnimatorDelta
```

### 8.5 速度空间交接

视觉动画继续 CrossFade，但机械运动在速度空间交接：

$$
v(t)=(1-w_m(t))v_s+w_m(t)v_t
$$

KCC 使用：

$$
\Delta p=v(t)\Delta t
$$

其中机械运动权重 $w_m$ 可以独立于视觉 CrossFade 权重。

Locomotion 建议默认：

```text
Visual Fade Duration：0.10～0.15s
Motion Blend Duration：0.08～0.12s
```

### 8.6 Root Motion 重定向顺序

`RootMotion + MoveDirection` 模式当前会保留 Root Motion 平面速度大小，并重定向到输入方向。

建议处理顺序固定为：

```text
采集原始 Delta
→ 代次与所有权校验
→ 异常检测
→ 速度连续性处理
→ 轴权重
→ MoveDirection 重定向
→ 提交 CharacterVelocity
```

不能先重定向再判断异常，否则会丢失原始异常方向信息。

## 9. P2：StateController 提交流程优化

### 9.1 当前风险

当前先退出源状态，再创建和进入目标状态。若目标动画加载失败，系统可能出现：

- 旧状态已经结束；
- 旧 Movement Policy 已释放；
- 目标逻辑状态已安装但动画失败；
- Root Motion Owner 暂时为空；
- 动画和逻辑状态不一致。

### 9.2 建议的事务流程

```text
1. ValidateTransition
2. PrepareTargetStateRuntime
3. PrepareTargetAnimation
4. ResolveTransitionProfile
5. BeginRootMotionBarrier
6. CommitLayerRuntime
7. SwapMovementPolicy
8. CommitAnimationTransition
9. ApplyTags / RemoveOldTags
10. FinalizeOldState
11. EmitNotification
```

关键要求：

- 目标动画准备失败时不破坏旧状态；
- 同层切换过程中 Layer 槽位不为空；
- Movement Policy 使用原子替换，不经历默认策略空窗；
- Root Motion Owner 使用原子替换；
- 动画交接成功后再完成旧状态清理；
- 通知只在完整提交后发送。

### 9.3 Movement Policy 原子替换

建议为 `CharacterMovementPolicyController` 增加替换操作：

```text
Replace(oldHandle, newOwner, priority, newProfile)
```

避免当前：

```text
Release(old)
→ Current 短暂回退
→ Submit(new)
```

虽然这些操作目前发生在同一个 Update，但原子替换能明确保证观察者和后续扩展不会读取中间状态。

## 10. P3：视觉根与机械根分离

推荐最终预制体：

```text
CharacterRoot
├─ KinematicCharacterMotor
├─ CustomCharacterController
├─ CharacterVelocity
├─ CharacterRotation
└─ VisualRoot
	 ├─ Animator
	 ├─ Animancer
	 ├─ RootMotionSource
	 └─ Character Model
```

职责：

- `CharacterRoot`：机械位置、旋转、碰撞和网络同步；
- `VisualRoot`：动画姿势、视觉偏移和表现修正；
- `RootMotionSource`：把 Visual Root 的动画 Delta 转交给机械运动解析器；
- Animator 永远不直接驱动机械根。

迁移时需要同步检查：

- 武器和特效挂点；
- HitBox/HurtBox 所属根；
- 相机 Follow/LookAt；
- 锁定目标点；
- 技能预览实例；
- 网络同步组件；
- 模型朝向和比例；
- 动画事件接收对象。

## 11. P3：烘焙机械 Root Motion 曲线

仅依赖 `Animator.deltaPosition` 的最终混合结果，难以彻底分离视觉 Pose 混合和机械运动。

生产级最终方案是从动画中提取并烘焙：

```text
LocalForwardVelocityCurve
LocalSideVelocityCurve
VerticalVelocityCurve
YawVelocityCurve
```

运行时根据状态动画时间直接采样曲线，由 Root Motion Resolver 负责混合，再交给 KCC。

此时职责变为：

```text
Animancer CrossFade → 只负责视觉 Pose
Root Motion Curves → 负责机械速度
State Transition Policy → 决定机械速度如何交接
KCC → 执行最终运动
```

优点：

- 不受独立 FBX 根绝对坐标影响；
- 不受 PlayableGraph Pose CrossFade 的根位置差影响；
- 可精确控制攻击、冲刺和处决位移；
- 更容易实现网络预测与回放；
- 更容易做帧率一致性测试；
- 可在编辑器中可视化速度和累计位移。

为了兼容旧资源，应保留两种数据源：

```text
AnimatorDelta（兼容模式）
BakedMotionCurves（正式模式）
```

## 12. 数据配置建议

建议在动画或状态配置中增加：

```text
RootMotionSourceMode
RootMotionTransitionPolicy
MotionBlendDuration
TransitionGraceSamples
MaxRootMotionSpeed
MaxRootMotionAcceleration
RejectOppositeMotionOnForwardIntent
PreserveSourceVelocityOnEnter
RootMotionOwnerPriority
```

推荐默认配置：

### Locomotion

```text
Visual Transition：0.10～0.15s
Motion Policy：BlendVelocity + ClampDiscontinuity
Motion Blend：0.08～0.12s
Grace Samples：1～2
Owner：Locomotion
```

### Root Motion 攻击

```text
Visual Transition：按动作配置
Motion Policy：TargetDominant / AuthoredMotion
Owner：Action
安全速度钳制：开启
```

### Idle

```text
Animator Capture：保持开启
TranslationMode：Locked 或 Input
RotationMode：按状态策略
采集到但不属于 Owner 的 Delta：显式丢弃
```

## 16. 风险与兼容策略

### 16.1 不一次性重写全部系统

按 P0、P1、P2、P3 分阶段提交。每阶段独立验收，避免同时修改状态机、动画层和 KCC 后无法定位回归来源。

### 16.2 保留旧接口适配层

旧调用暂时通过 Adapter 转发到新接口，确认所有调用点迁移后再删除，避免技能预览、编辑器预览或测试角色突然失效。

### 16.3 保留 Raw 模式

所有连续性修正都必须可以切换回 `RawAnimatorDelta`，以便：

- 对比修正前后数据；
- 判断异常来自资源还是管线；
- 避免安全钳制掩盖真正配置错误。

### 16.4 精确位移动作不能使用普通 Locomotion 策略

处决、突进、投技等动作可能有很高的合法速度或瞬时方向变化。它们必须使用动作专属阈值和 Owner 策略，不能被 Locomotion 的异常检测误杀。

---

## 17. 结论

当前问题不是简单把 CrossFade 调小即可解决。`Transition Duration = 0` 只能减少混合 Root Motion 的异常，但会牺牲视觉衔接，并保留切换边界的一次性位移风险。

正式优化路线应当是：

1. 先把“Stop 旧动画 + Play 新动画”改为原子同层交接；
2. 让 Animator Root Motion 捕获保持稳定，由 Movement Policy 决定是否消费；
3. 为状态切换建立 Root Motion Generation 和 Barrier；
4. 在速度空间进行机械 Root Motion 交接，同时保留视觉 Pose CrossFade；
5. 最终使用烘焙运动曲线彻底解耦视觉动画和机械位移。

完成 P0～P2 后，`Run_Start → Run` 应能使用正常的非零 CrossFade，同时做到视觉丝滑、胶囊不后退；完成 P3 后，整套系统将具备支持高规格 ARPG Locomotion、位移技能和复杂动画分层的稳定基础。
