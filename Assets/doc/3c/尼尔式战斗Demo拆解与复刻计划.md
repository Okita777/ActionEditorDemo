# 尼尔式战斗 Demo 拆解与复刻计划

## 1. 文档目的

本文以《尼尔：机械纪元》一类高速、自由取消、移动与攻击高度连续的动作体验作为参考，制定一个可执行的 Demo 拆解与复刻流程。

目标不是一比一复制商业游戏，也不是复制其内部实现，而是：

1. 研究公开可观察的操作规律。
2. 将手感拆成可测量的输入、状态、动画、运动、镜头和反馈参数。
3. 使用当前 3C 与技能编辑器实现一个相似的战斗纵切片。
4. 在实现过程中发现编辑器缺口。
5. 将重复出现的缺口逐步建设为通用能力。

最终 Demo 使用自有或合法授权的动画、模型、特效和音效。

---

## 2. 复刻范围

第一阶段只复刻单角色的基础操作闭环，不复刻完整游戏内容。

### 2.1 第一阶段包含

1. Idle、启动、移动、停止和急转。
2. 非锁定和锁定移动。
3. 三段地面轻攻击。
4. 一段重攻击。
5. 移动攻击。
6. 高速闪避。
7. 闪避后奔跑或高速移动。
8. 闪避攻击。
9. Recovery 被移动、攻击和闪避取消。
10. 基础攻击朝向辅助。
11. 一个带明显位移的突进攻击。
12. 木桩敌人的基础受击和命中反馈。

### 2.2 第一阶段不包含

- 完整双武器组合。
- Pod 射击并行系统。
- 空中完整连段。
- 完整击飞、倒地和受身。
- 处决和双人同步动画。
- 多角色切换。
- Boss 专属机制。
- 对原作动画和资源的一比一复制。

这些内容只在基础操作稳定后逐步加入。

---

## 3. 目标战斗哲学

第一阶段先明确以下设计原则：

1. **响应优先**：输入后尽快产生可信动作反馈。
2. **普通攻击承诺较低**：Recovery 可被移动、攻击和闪避取消。
3. **重攻击承诺较高**：起手和 Active 阶段拥有更严格取消限制。
4. **移动连续**：攻击结束后能快速恢复移动，不产生明显停顿。
5. **闪避高优先级**：多数普通动作允许在合理窗口转入闪避。
6. **朝向辅助适中**：帮助玩家对准目标，但不能出现强烈瞬移式旋转。
7. **命中反馈分级**：轻攻击、重攻击和终结段使用不同反馈强度。

建议首版优先级：

```text
死亡/强制状态
> 有效受击
> 闪避
> 技能/重攻击
> 普通攻击连段
> 移动
> 自然结束
```

这只是 Demo 基线，后续根据实测调整。

## 4. 研究与取样方法

## 4.1 参考素材准备

每个研究动作至少准备：

1. 正常速度录屏。
2. 60 FPS 或更高帧率录屏。
3. 固定镜头距离。
4. 平地、无敌人版本。
5. 对木桩命中版本。
6. 挥空版本。
7. 靠墙版本。
8. 锁定与非锁定版本。
9. 不同输入时机的取消版本。

尽量保证输入、角色距离和目标位置可重复。

## 4.2 逐帧记录

不要只记录“这个动作很快”。每个动作填写统一分析表：

| 分类 | 字段 | 示例 |
| --- | --- | --- |
| 输入 | 触发方式 | 短按轻攻击 |
| 输入 | 缓冲时长 | 待测 |
| 状态 | Startup | 约 8 帧 |
| 状态 | Active | 约 5 帧 |
| 状态 | Recovery | 约 14 帧 |
| 取消 | 移动取消起点 | 命中后若干帧 |
| 取消 | 下一段输入窗 | Active 后段至 Recovery |
| 动画 | 总时长 | 待测 |
| 动画 | Fade In / Out | 待测 |
| 运动 | 总位移 | 待测米数 |
| 运动 | 可转向窗口 | Startup 前段 |
| 命中 | HitStop | 待测 |
| 镜头 | Shake / FOV | 待测 |

如果无法确定精确数值，先记录区间和主观等级，再通过 Demo A/B 测试收敛。

## 4.3 输入可视化

录制时建议同时显示输入：

- 移动轴。
- 攻击按下帧。
- 闪避按下帧。
- 锁定状态。
- 当前目标。

自己的 Demo 也应提供同类调试信息，便于对齐“输入发生”和“动作真正开始”的时间差。

## 4.4 位移测量

在参考和 Demo 中都使用统一尺度：

1. 角色身高作为参照。
2. 地面绘制固定间距网格。
3. 记录动作开始和结束位置。
4. 区分动画 Root Motion 位移与目标吸附修正。
5. 分别记录挥空和命中时位移。
6. 测试目标距离不同时的位移差异。

## 4.5 并排对比

每个动作至少进行：

1. 正常速度并排播放，比较整体节奏。
2. 0.25 倍速逐帧比较。
3. 对齐输入帧。
4. 对齐第一帧明显动作反馈。
5. 对齐命中帧。
6. 对齐角色停止或进入下一动作的帧。

优先对齐行为规律，而不是完全对齐动画姿势。

## 5. 动作拆解模型

每个攻击统一拆成：

```text
Input Buffer
→ Startup
→ Active
→ Recovery
→ Default / Next Attack / Move / Dodge
```

### 5.1 Startup

研究：

- 输入后多久开始动作。
- 起手是否允许转向。
- 是否有前置位移。
- 是否能被闪避取消。
- 是否能被受击打断。
- 是否已经消耗资源或进入冷却。

### 5.2 Active

研究：

- HitBox 生效范围和持续时间。
- 单目标是否只命中一次。
- 是否有多段命中。
- 命中和挥空是否产生不同后续。
- 命中时位移是否停止。
- HitStop 是否冻结攻击者与受击者。

### 5.3 Recovery

研究：

- 自然后摇时长。
- 移动取消时机。
- 下一段攻击取消时机。
- 闪避取消时机。
- 取消是否保留连段。
- 不输入时何时回到默认状态。

在当前设计中，Recovery Cancel 只取消后摇状态，不破坏技能图连段进度。

## 6. Demo 角色最小动作集

## 6.1 Locomotion

第一轮配置：

- Idle。
- DirectionalMixer2D 移动。
- 启动和停止先视素材情况决定是否独立 State。
- 180 度急转。
- 普通转向。
- 锁定时绕目标移动。

需要记录：

- 最大速度。
- 加速度和减速度。
- 急转判定角度。
- 急转速度保留。
- 转向速度。
- 动画步频匹配范围。

验收：

- 不明显滑步。
- 输入反向时不拖泥带水。
- 锁定绕行不产生朝向抖动。
- 松手后停止距离合理。

## 6.2 三段轻攻击

建议结构：

```text
Light1 Execute → Light1 Recovery
Light2 Execute → Light2 Recovery
Light3 Execute → Light3 Recovery
```

技能图维护段数；每段 Execute / Recovery 都是 Action 层 State。

每段配置：

- 动画 Clip。
- Timeline Duration。
- 动画起播和 Fade。
- HitBox。
- HitStop 监听窗口。
- CameraShake 监听窗口。
- HitVfx 和 HitAudio。
- 运动策略。
- Recovery 默认后继。

差异设计：

| 动作 | 节奏 | 位移 | 反馈 |
| --- | --- | --- | --- |
| Light1 | 快速起手 | 小 | 轻 |
| Light2 | 稍强推进 | 中 | 中 |
| Light3 | 明确终结 | 大或停顿明显 | 强 |

必须测试：

- 静止三连。
- 按住移动时三连。
- 每段 Recovery 移动取消后再继续连段。
- 提前输入下一段。
- HitStop 期间输入下一段。
- 超时后重新从第一段开始。
- 冷却、资源或状态门禁失败时不破坏当前状态。

## 6.3 重攻击

第一版只做一个地面重攻击，用于验证更高动作承诺：

- Startup 较长。
- 位移更明显。
- Active 更强。
- Recovery 可取消时间更晚。
- 更强 HitStop、Shake、VFX 和 Audio。
- 更高韧性伤害预留。

如果当前 Recovery 策略只能全程取消，而目标动作需要“后摇前半段不可取消”，应先确认不可取消部分是否应归入 Execute；不要立刻增加复杂 Recovery 时间矩阵。

## 6.4 高速闪避

闪避需要拆解：

1. 输入响应帧。
2. 位移距离和速度曲线。
3. 无敌帧。
4. 可转向窗口。
5. 结束后是否进入高速奔跑。
6. 能取消哪些攻击阶段。
7. 闪避是否保留原连段。
8. 连续闪避间隔。

第一版 State：

```text
Dodge Execute → Dodge Recovery / Run
```

建议闪避拥有高于普通技能和移动的请求优先级，但是否能取消重攻击 Startup 必须由动作规则明确决定。

## 6.5 闪避攻击

用于验证状态上下文派生：

```text
Dodge → DodgeAttack Execute → Recovery
```

触发条件不是普通攻击入口，而是“当前或最近处于 Dodge 上下文”。需要测试：

- 闪避早期输入。
- 闪避尾端输入。
- 输入缓冲。
- 闪避结束后超时是否退化为普通攻击。

## 6.6 移动攻击

用于验证 Locomotion 与 Action 协作：

- 有移动速度或移动输入时进入移动攻击。
- 起手方向优先使用移动方向。
- 动作后恢复移动。
- 锁定时可能优先朝目标修正。

不要仅根据当前动画判断是否在移动，应使用运动事实和输入快照。

## 6.7 突进攻击

用于验证技能运动和目标适配：

- 无目标时按角色前方推进。
- 有目标时在有限角度内修正朝向。
- 目标过近时缩短位移。
- 目标过远时不无限吸附。
- 靠墙时不穿透。
- 命中后是否停止或继续穿行需明确。

---

## 7. 攻击朝向拆解

需要分别测试：

1. 无目标、无移动输入。
2. 无目标、有移动输入。
3. 有锁定目标在正前方。
4. 目标位于侧面。
5. 目标接近背后。
6. 连段中目标横向移动。
7. 原目标死亡后附近存在第二目标。

首版推荐规则：

- 普通攻击起手时优先面向有效攻击目标。
- 没有目标时面向移动或镜头输入方向。
- 每段连击开始时允许重新修正。
- Active 后停止大幅追踪。
- 最大修正角和角速度有限制。

记录以下参数：

- 选取半径。
- 水平扇形角。
- 最大瞬时修正角。
- 持续追踪时间。
- 转向速度。
- 目标丢失策略。

---

## 8. 运动拆解

每个动作绘制近似速度曲线：

```text
速度
 ^        /\
 |       /  \____
 |______/         \____
 +----------------------> 时间
       Startup Active Recovery
```

至少区分：

- 输入速度。
- Root Motion 速度。
- 目标修正速度。
- 外力速度。

首版可以通过动画 Root Motion 与状态运动策略实现；如果多个攻击都需要距离适配，再引入通用 Motion Warping。

测试：

- 空挥。
- 近距离命中。
- 最大辅助距离命中。
- 目标远离。
- 目标横移。
- 靠墙。
- 斜坡。
- 台阶。

---

## 9. 命中反馈拆解

## 9.1 分级

建议先定义三档反馈：

| 等级 | 适用 | HitStop | Shake | VFX / Audio |
| --- | --- | --- | --- | --- |
| Light | 第一段轻攻击 | 短、弱 | 很弱 | 清脆、较小 |
| Medium | 第二段或重命中 | 中 | 中 | 更明显 |
| Heavy | 终结段或重击 | 较长 | 强但限幅 | 大型、低频加强 |

具体数值通过 A/B 测试确定，不应只追求停顿越长越有力。

## 9.2 命中与挥空差异

研究：

- 挥空音效。
- 命中音效是否覆盖或叠加挥空音效。
- 武器拖尾。
- 命中特效方向。
- 命中时攻击动画是否视觉停顿。
- 攻击者和敌人是否使用不同比例的停顿。
- 多目标命中时反馈是否限流。

## 9.3 反馈叠加

需要防止：

- 多个敌人同帧命中导致 Shake 无限叠加。
- 多段攻击触发重复音效。
- VFX 池中实例未回收。
- HitStop 导致输入或 Timeline 丢失。

---

## 10. 相机拆解

第一阶段只做玩法相机，不做复杂演出镜头。

记录：

- 跟随距离。
- 高度。
- Pitch 范围。
- 普通移动 FOV。
- 高速移动 FOV。
- 锁定构图。
- 攻击时偏移。
- Shake 方向、强度、频率和衰减。
- HitStop 时相机是否继续运动。

测试：

- 目标正前方和侧面。
- 近距离锁定。
- 大型目标。
- 墙角。
- 狭窄通道。
- 目标高于或低于玩家。

第一阶段优先保证舒适和可读，不追求大量镜头特写。

## 11. Benchmark 测试场景

建立固定场景：

1. 带米制网格的平地。
2. 90 度墙角。
3. 狭窄通道。
4. 斜坡。
5. 台阶。
6. 小型静止木桩。
7. 小型移动木桩。
8. 大型体积木桩。
9. 多目标圆形分布。
10. 高低差目标。

建议场景内提供：

- 当前输入显示。
- 当前 Locomotion / Action State。
- 当前技能 Node。
- Execute / Recovery 阶段。
- State 时间。
- Root Motion 和最终速度向量。
- 当前攻击目标。
- 活动 HitBox。
- 最近取消原因。

## 13. 每个动作的制作流程

对每一个新动作执行同一流程：

### 步骤 1：建立参考样本

- 录制正常速度和慢速视频。
- 记录输入。
- 测量主要帧点和位移。

### 步骤 2：写动作规格

至少写明：

- 输入。
- Startup / Active / Recovery。
- 取消来源和时间。
- 位移和转向。
- 命中规则。
- 反馈等级。
- 默认后继。

### 步骤 3：只用现有编辑器配置

先不要改代码，确认当前工具能表达多少。

### 步骤 4：记录差异

使用三类标签：

- `Config`：已有能力，参数未调好。
- `Runtime`：底层没有所需行为。
- `Editor`：运行时能做，但配置效率或可见性不足。

### 步骤 5：判断是否通用

- 只出现一次：先保留动作特例。
- 两个以上动作都需要：考虑抽象。
- 多个角色都需要：升级为单位 Profile 或全局系统。

### 步骤 6：实现最小扩展

避免同时重构多个无关系统。

### 步骤 7：回归

新能力必须回测已完成动作，防止修复新动作时破坏旧连段和取消规则。

## 15. 第一轮验收清单

### 操作

- 输入响应稳定。
- 连段不随机回第一段。
- Recovery 任何合法取消不破坏连段。
- 连段超时后正确重置。
- HitStop 和低帧率下不丢输入。

### 动画

- 三段攻击过渡无明显闪帧。
- 移动和攻击切换自然。
- 闪避进入和退出自然。
- 动画速度调整后 Timeline 不错位。

### 运动

- 攻击位移不穿墙。
- 不轻易穿过目标。
- 斜坡和台阶基本稳定。
- 锁定转向不抖动。

### 反馈

- 三段反馈强度可辨识。
- 多目标命中不造成反馈爆炸。
- VFX、Audio 和 HitStop 时序稳定。

### 工具

- 能观察当前状态和技能节点。
- 能定位状态请求失败原因。
- 配置一个新攻击不需要修改通用代码。
- 预览结果与运行时大体一致。

## 16. 第一轮最可能推动的编辑器扩展

预计优先出现：

1. 正式 Input Buffer 面板。
2. 取消来源对应的动画过渡配置。
3. 攻击朝向策略配置。
4. 技能运动或位移曲线轨道。
5. HitBox 与动画帧对齐辅助。
6. 状态、技能节点和请求历史调试器。
7. 配置校验器。
8. 动作模板与轨道复制。

这些只是预期，不应在真实动作证明需要之前全部预先开发。

## 17. 后续扩展路线

基础 Demo 稳定后，可按顺序增加：

1. 重武器和轻重攻击组合。
2. 远程射击与近战并行。
3. 跳跃和空中轻攻击。
4. 空中闪避。
5. 挑空和空中追击。
6. 韧性、霸体和重硬直。
7. 精确闪避反击。
8. 多武器动画集。
9. Motion Warping。
10. 处决和同步动作。

每次只增加一个主要变量，避免无法判断手感变化来自哪个系统。

## 18. 最终执行建议

第一轮不要以“完全像原作”为目标，而以以下结果为目标：

1. 基础移动连续、舒适。
2. 三段轻攻击节奏清楚。
3. 移动、攻击和闪避取消可预测。
4. 连段在各种取消后仍正确。
5. 攻击大多数时候能自然面向合理目标。
6. 命中反馈具有明确层级。
7. 所有关键状态变化都可以调试和解释。
8. 新动作推动的编辑器扩展具有复用价值。

当这个纵切片稳定后，再决定哪些《尼尔》式高级系统值得继续复刻，哪些应改造成项目自身的战斗风格。
